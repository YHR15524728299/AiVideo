# 基线治理

## 权威顺序

1. 自动化测试与可重复运行证据。
2. SQLite 中的 Job 状态与 Repository 事务。
3. Worker 身份、租约和生命周期记录。
4. 由 Repository 生成的 `status.json` 快照。
5. GUI 内存视图和展示文本。

低层级信息不得覆盖高层级事实。GUI 不得直接写业务状态快照。

## 变更规则

- 先诊断，再计划，再实施。
- 状态、持久化、进程安全和公共行为变更必须测试先行。
- 每个模块切片完成后更新检查点和证据。
- 未通过全量测试、覆盖率、编译检查与差异检查时，不得宣称完成。
- 外部服务不可用只能记录为环境阻塞，不得伪装为成功。
