# 可靠资料研究设计

## 目标

让资料研究不再依赖模型凭空编写网址，并确保失败后的重试会真正寻找新来源，而不是重复使用已经失败的缓存结果。普通用户应能直接看到失败原因，并能用“重新搜索资料”继续任务。

## 成功标准

- 研究模型只能从系统提供的、已确认可访问的候选来源中选择 URL。
- HTTP 404、410 等确定性失效来源不会对同一 URL 重试。
- 外层任务恢复时会开启新的研究尝试，不读取上一次失败研究的生成缓存。
- 涉及“最新、当前、今年、下半年”等时效表达时，核心来源必须满足资料时效要求。
- 至少达到配置的验证通过数量和比例后，研究阶段才可完成。
- GUI 显示可理解的失败摘要，并提供“重新搜索资料”操作。
- 已有正常缓存行为、来源安全校验和断点恢复能力不退化。

## 非目标

- 不建设通用互联网搜索引擎。
- 不自动购买付费数据或绕过网站访问限制。
- 不降低 SSRF、公网 URL、响应大小和正文支持度等安全校验。
- 不保证每个选题都有足够公开资料；资料不足时必须明确失败。

## 架构边界

### 来源发现

新增独立的 `SourceDiscovery` 边界，输入为选题、内容方向、时效要求和已拒绝 URL，输出为候选来源：

- `url`
- `title`
- `published_at`，无法确认时为空
- `source_type`
- `query`

第一版使用可替换的搜索提供者接口。生产默认实现通过公开搜索能力返回候选 URL；测试使用内存假实现，不访问互联网。

来源发现只负责找到候选，不判断事实是否成立。

### 来源预检

复用 `SourceVerifier` 的 URL 安全与可达性能力，对候选来源进行轻量预检：

- 404、410：标记为永久拒绝，本轮和后续修复轮次不再访问。
- 403、429、5xx、超时：标记为临时失败，按现有退避策略有限重试。
- 私网、文件协议、超大响应、反爬页面：继续拒绝。

预检通过后，才将候选来源交给研究模型。

### 受约束研究

`ResearchEngine` 的输入新增 `source_candidates`。系统提示明确要求：

- `source_url` 必须逐字来自候选列表。
- 不得新增、改写或猜测 URL。
- 无法由候选来源支持的说法放入 `unknowns`。
- 每条核心事实记录来源日期；有时效要求时优先选择有效期内来源。

模型返回后，`SourceVerifier` 继续逐条验证正文是否支持 claim。来源发现和事实验证保持两个独立所有者。

### 研究尝试与缓存

新增 `research_attempt_id`，每次用户点击“重新搜索资料”或 Worker 对失败研究发起新的外层恢复时生成新值。

- 同一次研究尝试内允许缓存，避免重复计费。
- 新的研究尝试不读取旧尝试的研究生成缓存。
- 方向分析、选题、脚本等其他阶段缓存不受影响。
- 被拒绝 URL 会写入任务级 `research_rejections.json`，新尝试将其传给来源发现组件。

这取代“全局删除 OpenRouter 缓存”的粗暴方案。

## 数据流

1. 根据选题生成搜索查询和时效要求。
2. 来源发现返回候选 URL。
3. 预检过滤不可达、危险或永久失效 URL。
4. 研究模型仅从预检通过的候选中组织事实。
5. 来源验证器逐条检查正文支持度。
6. 验证不足时，把失败原因和拒绝 URL 反馈给下一修复轮次。
7. 三轮仍不达标时进入 `FAILED_RETRYABLE`，保存结构化失败摘要。
8. 用户点击“重新搜索资料”后创建新尝试，从新候选继续，不复用旧研究缓存。

## 时效规则

从方向和选题中识别时效表达：

- “最新、当前、今日、本周、本月、今年、下半年”：核心资料优先在最近 12 个月内。
- 明确年份：以该年份及相邻必要背景资料为主。
- 法律、制度、定义等稳定资料可不受 12 个月限制，但不能代替当前数据。

第一版不做复杂自然语言日期推理，只输出 `freshness_required` 和 `cutoff_date` 两个明确字段。无法确定发布日期的来源不能作为“最新数据”核心依据。

## 质量门槛

默认要求：

- 至少 5 条事实验证通过。
- 验证通过比例不低于 60%。
- 核心结论至少有 2 个独立来源或 1 个权威一手来源。
- 核心时效事实必须满足截止日期。
- 404/410 来源计为永久拒绝，不参与重复重试。

这些值放入研究策略配置，测试可覆盖边界值。

## GUI 行为

历史任务处于资料研究失败时，状态提示显示：

> 资料研究失败：8 条资料中 7 个网页不存在，1 条内容无法证明相关说法。

操作按钮：

- `重新搜索资料`：为当前任务创建新研究尝试并从 `RESEARCHED` 恢复。
- `查看失败详情`：打开简化详情，列出失败数量和分类，不直接展示技术堆栈。

运行日志仍保留完整技术信息。

## 错误分类

- `PERMANENT_SOURCE_FAILURE`：404、410、非法 URL、私网 URL。
- `TEMPORARY_SOURCE_FAILURE`：429、5xx、超时、连接失败。
- `UNSUPPORTED_CLAIM`：网页可访问但无法证明 claim。
- `INSUFFICIENT_FRESHNESS`：资料太旧或发布日期未知。
- `INSUFFICIENT_EVIDENCE`：通过数量或比例不足。

错误分类由来源验证层产生，GUI 只负责翻译和呈现，不重新推断。

## 兼容与迁移

- 现有 `research.json` 和 `research_sources.json` 保持兼容。
- 新增文件是可选的；旧任务没有 `research_attempt_id` 时按首次尝试处理。
- 现有任务 `260806` 可通过“重新搜索资料”生成新尝试，无需删除前四个已完成阶段。
- 旧的全阶段“继续/恢复”仍保留，但资料研究失败时 GUI 优先展示专用操作。

## 测试

- 单元测试：404 不重试、5xx 有限重试、候选 URL 白名单、时效规则、质量门槛、错误摘要。
- 缓存测试：同一尝试命中缓存，新尝试绕过旧研究缓存，其他阶段缓存不受影响。
- 流程测试：发现候选、预检、受约束研究、验证通过并落盘。
- 失败流程：候选不足、全部 404、正文不支持、时效不足。
- GUI 测试：资料研究失败显示专用按钮和用户可理解摘要。
- 回归测试：完整测试套件和 80% 覆盖率门槛。

## 实施顺序

1. 建立错误分类、研究策略和尝试 ID。
2. 修复外层研究恢复命中旧缓存的问题。
3. 增加来源发现接口和预检。
4. 将研究模型改为候选 URL 白名单。
5. 增加时效与质量门槛。
6. 增加 GUI 专用恢复和失败摘要。
7. 用任务 `260806` 做非破坏性恢复验证。
